# Emby 媒体菜单、任务进度与字幕完成刷新设计

## 范围

本次仅覆盖 Emby 中的电影和单集视频。剧集、整季、音乐及其他媒体类型不在范围内。

## 架构

- Emby 插件注册视频媒体菜单动作“生成云字幕”。
- 动作读取当前媒体路径、ItemId、标题、海报 URL 和 AV 号，按配置中的路径映射转换输入路径后调用现有 `/api/plugin/jobs`。
- 插件配置页继续作为插件 Web 页面，增加任务进度区域、轮询逻辑和刷新结果展示。
- 后端复用已有 `source=emby` 任务记录及 `/api/plugin/jobs`、`/api/plugin/jobs/{id}`、`refresh-result` 接口，不新增任务系统。

## 路径映射

配置格式为每行一条 `EmbyPrefix=ServicePrefix`，例如：

```text
D:\\Media=/media
\\\\nas\\Movies=/mnt/movies
```

提交任务前使用最长匹配的 Emby 前缀替换为服务前缀，并保留剩余相对路径。没有匹配项时提交原始路径。输出目录使用媒体文件所在目录，使生成字幕与媒体保持同目录并可被 Emby 发现。

## 任务进度页

- 展示任务标题、状态、当前阶段、百分比、消息、创建/完成时间和输出字幕数量。
- 页面加载后轮询插件任务列表；轮询间隔采用固定短间隔并在页面隐藏时暂停。
- 状态包括排队、处理中、完成、失败和取消；错误消息直接展示。
- 完成任务显示元数据刷新状态，区分刷新中、刷新成功及“字幕已完成，刷新失败”。

## 完成后的元数据刷新

- 任务完成且存在输出字幕后，插件调用 Emby 的对应 Item 元数据刷新接口。
- 刷新失败自动重试最多 3 次，采用递增等待间隔。
- 三次均失败时不改变字幕任务的完成状态，只通过 `refresh-result` 回写失败原因和状态，供进度页显示。
- 刷新成功通过同一接口回写成功状态。

## 错误处理与兼容性

- 插件 API 使用现有令牌认证；HTTP 非成功响应转换为用户可见错误。
- 无法读取路径、映射配置格式错误或 Emby 刷新请求失败时，不删除任务记录和已生成字幕。
- 现有非 Emby 任务行为保持不变；旧任务缺少刷新字段时按 `pending` 处理。

## 测试策略

- 插件端测试路径映射最长匹配、菜单动作请求体、任务轮询和刷新重试。
- Python 端测试插件任务路径/字段兼容及刷新状态接口。
- 运行现有测试套件与插件静态契约检查。
